### 1.2 功能清单（均已提交且端到端验证）

**后端（7 组 Controller）**
- 学生：注册/登录（JWT）、分页+关键词筛选、增改查、逻辑删除，学号唯一约束
- 班级：CRUD + 分页 + 重名 409 + 逻辑删除（第一个全流程由我手写的模块）
- 用户与角色：教师注册→待审核→管理员通过/禁用（状态机）；admin/teacher/student 三角色
- 权限：方法级 `@PreAuthorize` + 403 JSON 处理器；JWT 携带 role claim
- 课程：CRUD + 分页 + credit 精度校验（decimal 0.5 步进）
- 选课：联合唯一防重复选课 + 批量名单查询（N+1 规避）
- 成绩：录入/按课程查询（两跳 join）/学生自助查询（数据隔离）

**前端（8 个页面）**
- 登录（深色玻璃卡 + 光斑背景）、主布局（角色过滤菜单）
- 学生管理、班级管理、课程管理、成绩与选课双栏、管理员审核
- 学生端首页：成绩统计四格（均分/最高/最低/门数）+ 我的成绩表 + 课程浏览

### 1.3 架构决策记录（为什么这么设计）

| 决策 | 理由 |
| --- | --- |
| 逻辑删除 + 不建物理外键 | `deleted` 标记与 FK 约束冲突；删班级不应级联炸成绩 |
| JWT 无状态 + role claim | 前后端分离下免 session；角色随 token 走，权限校验不查库 |
| 统一响应 `Result{code,message,data}` | 前端拦截器“剥壳”的前提；错误也有统一形状可弹 |
| 统一异常 → 状态码翻译 | 业务异常（409/404）与系统异常（500）分层；500 必打日志 |
| DTO 进 / VO 出 | 请求字段隔离校验；响应永不泄露 password 哈希 |
| 学号做登录身份 | name 可重复且会改，studentNo 唯一且稳定 |
| vite proxy 解跨域 | 开发期不动后端；生产换 Nginx 反代，同一思路 |

## 二、技术经验清单（按“血泪程度”排序）

### 2.1 环境与构建

1. **中文配置文件绝不用 `pwsh Set-Content`**——默认 UTF-16/BOM/GBK 三连坑，YAML 直接解析失败。一律用编辑器写 UTF-8 无 BOM。
2. **Maven 镜像仓库 ID 不一致会让离线构建失败**（"present, but unavailable"）——依赖从阿里云镜像下载，就得用配了同一镜像的 settings.xml 去解析。
3. **Windows 大小写不敏感**：git mv 改包名会报 Invalid argument，两步改名（先 _tmp 再小写）绕过。
4. **增量编译不清理旧产物**：包重构后旧 .class 残留 → 组件扫描扫到两个同名 bean → `clean test` 是重构后的标准动作。

### 2.2 后端

5. **@Valid 拦不住 JSON 反序列化错误**：`gender` 传"男"会在进 Controller 前抛 `HttpMessageNotReadableException`（HTTP 500），必须单独写 handler 翻译成 400。
6. **Spring Boot 4 用 Jackson 3，包名是 `tools.jackson.*`**——网上旧教程全是 `com.fasterxml.*`，照抄必失败。
7. **分页要装 `PaginationInnerInterceptor`**（3.5.9+ 拆到 mybatis-plus-jsqlparser），不装不报错但不生成 LIMIT——静默全表扫描。
8. **DTO 校验注解只管 Controller 入口**，Service 内部还要做“至少提供一个要修改的字段”这类业务校验。
9. **查重和唯一索引是两道防线**：先 selectCount 友好报 409，再加 DB 唯一索引兜底并发窗口，`DuplicateKeyException` 统一翻译。
10. **逻辑删除后 selectOne 要小心**：唯一索引不知道你的 deleted 标记，重新造已删学号会撞唯一键。

### 2.3 前端

11. **路由守卫死循环是静默失败**：权限不匹配 → 弹回 → 再被拒 → 白屏且无 Console 报错。守卫必须有“落地页也失败就 logout”的兜底。
12. **权限字符串要归一化**：DB 存小写、JWT 原样携带、路由写大写 → 教师登录永远不跳转。统一在一个出口 `.toUpperCase()`。
13. **登录 401 ≠ 会话过期 401**：同一个状态码两种语义，输错密码弹“登录失效”是体验事故，拦截器要分支处理。
14. **CSS 变量是暗色主题的正道**：Element Plus 靠重定向 `--el-*` 变量翻转对比度，逐个组件写覆盖样式是无底洞。
15. **SFC 顶层不放含 `<>` 的注释**——会被解析成幽灵标签，整个组件编译失败。
16. **pnpm 的硬链接 + Junction 结构**在 Windows 上很脆弱：缓存目录乱跑会让 node_modules 集体失效，重装是最后但有效的手段。

### 2.4 协作与工程习惯

17. **git add -A 是危险动作**：17050 个文件的 pnpm 缓存曾卷入提交。先 `git status` 再 add，缓存目录永远进 .gitignore。
18. **提交前 grep 秘密**：连占位密码都可能被误当成真实密码，推送前 grep 一遍并修掉（未推送时 amend 是正确操作）。
19. **“我说做了”不如“git diff 一下”**：验收以文件和提交记录为准，这是团队协作的互信基础。
20. **端到端验证先想清楚身份**：第一轮全 401 不是 bug，是忘了带 token——测试脚本要像真实用户一样先登录。

## 三、方法论收获（比技术更持久）

1. **先规划后动手**：五份规划文档让每一阶段有据可依，“每次只推进一个明确任务”的节奏避免了半成品堆积。
2. **契约先行**：前后端联调前先盘 DTO 字段（page vs pageSize 的教训），接口文档就是契约。
3. **小步提交**：24 个提交每个都是可工作的状态，任何一步都能回退——这是敢做暗色主题大改的底气。
4. **手写一遍 > 看十遍**：班级模块全流程手写后再 review，比看十个教程都有效；也因此诚实地承认前端“我来代写、事后教学”是正确的止损。
5. **会跑 ≠ 正确**：编译通过、测试通过、端到端通过是三件不同的事，验收清单要写进文档而不是记在脑子里。

## 四、诚实的不足清单

- 测试只有 1 个 contextLoads：**没有任何业务单元测试**（阶段6.1 马上补）；
- 无 CI/CD、无接口文档（Swagger 未接）、无 Docker 部署方案；
- 前端是代写的，我目前读得懂但写不动——教学课程在第0课暂停；
- Redis 登出黑名单（JWT 无法作废的真实缺陷）已排期未实施；
- 分页参数名 page/pageSize 在模块间不一致（历史欠账，改动需前后端同步）。
