# ClassHub 端到端验收测试清单

> 用途：每次功能改动后按本清单**手工回归**一遍，防止改 A 坏 B。
> 历史依据：清单中每一条都是开发过程中用 curl 实测通过的用例，固化成文档。
>
> **约定**
> - 后端默认 `http://localhost:8080`（本机 8080 被 IDEA 占用时用 18080）
> - `<T>` 表示替换为上一步响应里的 token 等动态值
> - 带 ★ 的为核心路径，必测；其余可在时间紧张时抽测
> - Windows PowerShell 下 JSON 报文含中文时，先存文件再 `curl.exe --data-binary @file`，避免控制台编码坑

## 0. 准备工作

1. 启动 MySQL，确认库 `studentmanage` 存在、已执行 `sql/` 下全部迁移脚本；
2. 启动后端（IDEA 运行 DemoApplication，或 `mvnw spring-boot:run`）；
3. 健康检查：`curl http://localhost:8080/student/1` 无 token → 应返回 401 JSON（而不是 403 或 500）。

## 7. 回归口径

- **每次后端改动**：至少跑第 1、2 章全部 ★ 用例 + 与改动模块相关的章节；
- **每次发版前**：全清单过一遍；
- 命令行回归模板（登录→存 token→带 token 调用）：

```powershell
# 登录取 token
$login = '{"username":"teacher_wang","password":"Abc12345"}'
Set-Content -Path tmp.json -Value $login -Encoding utf8
$t = (curl.exe -s -X POST http://localhost:8080/auth/login -H "Content-Type: application/json" --data-binary "@tmp.json" | ConvertFrom-Json).data.token
# 带 token 调用
curl.exe -s http://localhost:8080/student?page=1\&size=10 -H "Authorization: Bearer $t"
```
