## 5. 任务卡（按步骤拆解，含验收标准）

### 任务卡 A：创建项目
```powershell
cd D:\software\demo
pnpm create vue@latest web
```
交互选项：TypeScript **No**（降低第一遍复杂度）、JSX No、Router **Yes**、Pinia **Yes**、Vitest No、E2E No、ESLint Yes、Prettier Yes。
装依赖：`pnpm add element-plus axios` 然后 `pnpm dev`，浏览器见到默认首页即完成。
**验收**：`pnpm dev` 无报错，浏览器访问 localhost 端口有页面。

### 任务卡 B：路由骨架 + 空布局
`src/router/index.js` 定义路由表；`src/layout/MainLayout.vue` 用 Element Plus 的
`el-container`（侧边 `el-aside` + 顶栏 `el-header` + 主区 `el-main`）。
侧边栏菜单四项（学生/班级/课程/成绩），全部指向占位组件（先只放一行 `<h1>学生管理</h1>`）。
**验收**：点菜单能切换 URL，页面跟随变化（哪怕全是占位）。

### 任务卡 C：Axios 封装 + Pinia auth store（M3 核心）
`src/api/request.js`：创建 axios 实例，`baseURL: '/api'`。
- **请求拦截器**：从 localStorage 读 token，存在则加 `Authorization: Bearer <token>`。
- **响应拦截器**：`code===200` 时直接 `return res.data.data`（调用方拿到裸数据）；
  `code===401` 时清空本地登录态并跳 `/login`；其他非 200 用 `ElMessage.error(message)` 弹出后 `return Promise.reject(...)`。

`src/stores/auth.js`（Pinia）：`token`、`username`、`role`、`userType`（student/teacher）四状态 +
`login()`、`logout()` 两个 action，token 用 localStorage 持久化（刷新不掉线）。

`vite.config.js` 加 dev 代理：`'/api'` → `http://localhost:8080`，`rewrite` 去掉 `/api` 前缀。

**验收（纯手工可测）**：写一个临时按钮调 `GET /api/clazz?page=1&size=10`，
浏览器 Network 面板看到请求头带 Authorization、响应 200、控制台拿到 records 数组。

### 任务卡 D：登录页
双 Tab 表单（el-tabs），学生 Tab 提交 `/student/login`（studentNo+password），
教师 Tab 提交 `/auth/login`（username+password）。成功后把 token/用户名/身份存入 Pinia
并 `router.push('/students')`；失败让响应拦截器的 ElMessage 报错即可，登录页自己不用写错误提示。
登录页路由要加「免登录守卫」（未登录访问业务页 → 重定向 /login；已登录访问 /login → 放行或跳首页）。
**验收**：teacher_wang 能登录进主布局；错误密码弹「用户名或密码错误」；直接输 URL 访问 /students 会被踢回 /login。

### 任务卡 E：学生管理页（模板页，后面页面复制变式）
- `el-table` + `el-pagination`（total/records/page/size 四件套对接 PageResult）
- 顶部搜索框（keyword）+「新建学生」按钮
- 新建/编辑共用一个 `el-dialog` + `el-form`（rules 对齐后端 DTO：学号 `^S\d{9}$`、姓名 2-100、性别 0/1 radio、年龄 6-100、手机号 `^1[3-9]\d{9}$`）
- 删除用 `el-popconfirm` 或 `ElMessageBox.confirm`
- 对接：`GET /student`（分页）、`POST /student/register`、`PUT /student/{id}`、`DELETE /student/{id}`
**验收**：搜索张三只出张三；翻页 total 正确；新建后列表刷新能看到；删除后消失；非法表单（学号 10 位数字）前端红字拦截。

### 任务卡 F：班级页 + 课程页
复制任务卡 E 的结构改字段。班级（name/grade）；课程（name/credit，credit 用 `el-input-number` 0.5~10 步进 0.5）。
**验收**：两页 CRUD 全通；建课后返回列表能立刻看到新课程（这就是热身改动后 `data` 有值的意义）。

### 任务卡 G：选课与成绩页
- 左右双 `el-card`：左侧课程下拉（`GET /course` 全量或分页大 size）+ 选中后查选课名单 `GET /enrollments?courseId=`
- 名单每行一个「录成绩」按钮 → 弹窗（value 用 `el-input-number` 0~100）→ `POST /scores`
- 右侧该课程成绩列表 `GET /scores?courseId=`（学生姓名/学号/分数/考试类型）
- 教师身份访问 `/scores/my` 是 403——**不要在前端调用它**，但要在拦截器里确认 403 会弹错误消息（未来学生端接入时直接复用）
**验收**：选课程→看名单→录 88.5→右侧成绩列表出现这条；录第二个 88.5 被 409 拦截弹「已填加学生成绩记录」。

## 6. Review 常见雷区预告（M2 坑在前端的等价物）

1. **响应拦截器返回值**：`return res.data.data` 后，调用方拿到的已经是裸数据——别再 `.data.data` 叠罗汉。
2. **token 过期（2小时）**：所有接口突然全 401 → 拦截器统一踢回登录页，别在每页各写一遍。
3. **el-form rules**：和后端 DTO 校验规则保持一致，但**前端校验只是体验优化，后端才是安全边界**（你可以用 curl 绕过前端直接打后端验证这一点）。
4. **分页参数**：后端 DTO 是 `page`/`size` 还是 `page`/`pageSize`，以 StudentQueryDTO 实际字段名为准，别想当然。
5. **Element Plus 按需引入 vs 全量引入**：M3 全量引入（main.js 一行 `app.use(ElementPlus)`），体积优化不是现在的目标。
