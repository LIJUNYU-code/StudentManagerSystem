# 技术方案与数据库设计（推荐方向 B：一体化管理平台）

> 项目定位：**"ClassHub 学生班级一体化管理平台"**（名字可改）——面向中小班级/培训机构教务的老师端管理系统，二期升级为带数据分析的教学平台。
> 目标用户：教务管理员（admin）、任课老师（teacher）、学生（student，二期开放自助查看）。
> 原则：单体应用、解释得清、调试得动、逐步长大。**不引入微服务/消息队列/Redis/分布式**。

---

## 1. 功能清单与 MVP 划分

### MVP（第一版必须完成——做完即可演示）

| 模块 | 功能 |
|---|---|
| 认证 | 注册（教师自助注册→待管理员审核，或首个注册者自动为 admin）、登录（JWT）、退出（前端删 token）、修改密码 |
| 学生管理 | 学生列表（分页+按姓名/学号/班级筛选）、新增、编辑、删除（逻辑删除）、详情（**不返回密码哈希**） |
| 班级管理 | 班级 CRUD、班主任指定、班级学生名单 |
| 课程管理 | 课程 CRUD、任课老师指定 |
| 选课关系 | 学生↔课程 选课/退课（一个学生多门课，一门课多个学生） |
| 成绩管理 | 按课程录成绩（一次录全班）、按学生查成绩单、成绩修改（留修改记录） |
| 系统管理 | 教师账号审核（admin）、角色管理（admin/teacher 两种角色即够 MVP） |

### 二期扩展（按优先级排序）

1. **考勤**：按课程次打考勤（出勤/迟到/请假/缺勤），与成绩页联动
2. **数据分析（即方向 C）**：成绩趋势折线、班级分布直方图、排名变化（ECharts）
3. 学生自助端：学生登录后只能看自己的成绩/考勤
4. Excel 批量导入学生/成绩、导出成绩单
5. 通知公告、操作审计日志

### 明确不做（现在不应该碰的）

微服务拆分、Redis 缓存、消息队列、Docker 集群、OAuth2 第三方登录、WebSocket 实时推送、多租户。理由：单体+MySQL+JWT 完全撑得住这个数据量，先跑通业务再谈架构升级。

## 2. 前后端技术方案

| 层 | 选型 | 版本依据 |
|---|---|---|
| 后端 | Spring Boot（沿用 4.1.1）+ Spring MVC | 官方要求 Java 17~26（本机 26 合规） |
| ORM | MyBatis-Plus（沿用 spring-boot4-starter 3.5.17） | 官方文档确认 boot4 starter 自 3.5.13 起提供 |
| 数据库 | MySQL 8.0（沿用本机实例） | |
| 认证 | Spring Security + jjwt 0.12.6（沿用现有自研过滤器，补角色） | |
| 参数校验 | jakarta validation（沿用） | |
| API 文档 | springdoc-openapi（后续加，非必须） | |
| 前端 | **Vue 3 + Vite + Element Plus + Axios + Vue Router + Pinia** | 均官方免费；Element Plus 是 Vue3 生态最主流的管理后台组件库 |

## 3. 系统架构与代码包结构

单体三层架构（Controller → Service → Mapper → MySQL），前端独立工程通过 HTTP/JSON 调用：

```
浏览器(Vue3 SPA) ──HTTP+JWT──▶ Spring Boot(8080)
                                ├─ Controller   接口层：参数校验、调用Service、包装Result
                                ├─ Service      业务层：事务、业务规则
                                ├─ Mapper       数据层：MyBatis-Plus BaseMapper
                                └─ MySQL 8.0
```

### 后端包结构（顺带修正现有大写包名问题，按小写规范重组）

```
com.example.demo
├─ DemoApplication.java
├─ common/            Result统一响应、PageResult分页响应、常量、错误码枚举
├─ config/            SecurityConfig、MybatisPlusConfig(分页插件/填充器)、OpenApiConfig
├─ security/          JwtUtil、JwtAuthenticationFilter、LoginUser(含角色)、PasswordConfig
├─ exception/         BusinessException(业务异常基类,带错误码)、GlobalExceptionHandler
├─ controller/        AuthController、StudentController、ClazzController、CourseController、EnrollmentController、ScoreController
├─ service/           各业务接口 + impl/ 实现
├─ mapper/            各实体 Mapper
├─ entity/            Student、Clazz、Course、Enrollment、Score
└─ dto/               各接口的请求/响应对象（按 controller 子包组织）
```

### 前端工程结构（新建独立目录，如 `web/`）

```
web/
├─ src/
│  ├─ api/            按模块封装的 axios 请求
│  ├─ router/         路由 + 登录守卫
│  ├─ stores/         Pinia：token、当前用户信息
│  ├─ utils/request.js  axios实例：自动带token、统一拦截401/错误提示
│  └─ views/          login/、dashboard/、student/、clazz/、course/、score/
└─ vite.config.js     dev 代理 /api → http://localhost:8080
```

## 4. 数据库表设计

命名规范：表/字段全小写下划线，均含 `create_time datetime`、`update_time datetime`、`deleted tinyint`（逻辑删除 0/1），下表省略这三列。字符集 utf8mb4。

### 4.1 student（学生）— 改造现有表

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigint unsigned | PK, auto_increment | 主键 |
| student_no | varchar(20) | **UNIQUE**, NOT NULL | 学号，业务标识 |
| name | varchar(100) | NOT NULL, **INDEX(idx_name)** | 姓名——**加普通索引**（查重唯一性由学号保证，重名合法！） |
| gender | tinyint | NULL | 0男 1女——**与 Java Integer 对齐，替换现有 char(1)** |
| age | tinyint | NULL | 6-100 |
| phone | varchar(11) | UNIQUE, NOT NULL | 手机号（保留现有唯一约束） |
| clazz_id | bigint unsigned | NULL, INDEX, FK→clazz.id | 所属班级，可空（未分班） |
| password | varchar(255) | NOT NULL | BCrypt 哈希（学生二期才登录） |

> 相比现状的关键变化：`gender char(1)→tinyint`；`name` 撤掉查重职责（重名是现实，学号才唯一）；新增 `student_no`；id 从 int 升 bigint 与 MyBatis-Plus 默认雪花 ID 习惯对齐。
> **现有表中已有 phone 唯一索引**，phone 作为登录/找回凭证更合理，业务上保留。

### 4.2 clazz（班级）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigint unsigned | PK, auto_increment | |
| name | varchar(100) | UNIQUE, NOT NULL | 班级名（如"高一3班"） |
| grade | varchar(20) | NULL | 年级 |
| teacher_id | bigint unsigned | NULL, INDEX | 班主任（user.id） |

### 4.3 course（课程）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigint unsigned | PK, auto_increment | |
| name | varchar(100) | NOT NULL | 课程名 |
| teacher_id | bigint unsigned | NULL, INDEX | 任课老师 |
| credit | tinyint | DEFAULT 1 | 学分 |

> 同名课程可存在（不同老师各开一班课时用 name+teacher_id 组合区分），不做 name 唯一。

### 4.4 enrollment（选课关系）— 学生↔课程 多对多

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigint unsigned | PK, auto_increment | |
| student_id | bigint unsigned | NOT NULL, **UNIQUE(student_id, course_id)** | 联合唯一：防重复选课 |
| course_id | bigint unsigned | NOT NULL（同上联合） | |

### 4.5 score（成绩）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigint unsigned | PK, auto_increment | |
| enrollment_id | bigint unsigned | UNIQUE, NOT NULL, FK→enrollment.id | 一条选课关系一条成绩（改用 enrollment 关联避免 student×course 直连不一致） |
| value | decimal(5,1) | NOT NULL | 分数（支持 89.5） |
| exam_type | varchar(20) | NOT NULL, DEFAULT 'final' | 期中/期末/平时 |
| remark | varchar(255) | NULL | 备注 |

### 4.6 user（登录账号，教师/管理员；学生二期接入）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | bigint unsigned | PK, auto_increment | |
| username | varchar(50) | UNIQUE, NOT NULL | 登录名 |
| password | varchar(255) | NOT NULL | BCrypt 哈希 |
| real_name | varchar(100) | NOT NULL | 姓名 |
| role | varchar(20) | NOT NULL, DEFAULT 'teacher' | admin / teacher |
| status | tinyint | NOT NULL, DEFAULT 0 | 0待审核 1正常 2禁用 |

### 索引与外键策略

- 唯一索引：student.student_no、student.phone、clazz.name、enrollment(student_id,course_id)、user.username——**数据库层兜底防重**，业务层查重只是体验优化（先查后插+唯一索引双保险，并发安全）。
- 普通索引：student.name、student.clazz_id、clazz.teacher_id、course.teacher_id（列表筛选/关联查询用）。
- 外键：学习项目**建议建逻辑外键（应用层保证）+ 建表脚本中写注释**，不设物理外键约束——MyBatis-Plus 逻辑删除与物理外键会打架，这也是业界单体项目的常见取舍。

## 5. REST API 清单（统一前缀 `/api`，响应统一 `Result{code,message,data}`）

> 通用约定：成功 code=200；参数错 400；未登录 401；无权限 403；业务冲突 409；业务异常返回 200+code!=200（也可全走 HTTP 状态码，路线图阶段一定）。分页参数 `page`、`size`，返回 `PageResult{total,records}`。

| 方法 | 路径 | 参数 | 返回 | 权限 |
|---|---|---|---|---|
| POST | /api/auth/register | body: username,password,realName | 注册待审核 | 公开 |
| PUT | /api/auth/login | body: username,password | {token,name,role} | 公开 |
| POST | /api/auth/logout | - | 前端删token | 登录 |
| GET | /api/auth/me | - | 当前用户信息 | 登录 |
| PUT | /api/auth/password | body: oldPassword,newPassword | 改密 | 登录 |
| GET | /api/students | ?page,size,name,studentNo,clazzId | 分页学生列表 | admin/teacher |
| POST | /api/students | body: StudentDTO | 新增 | admin/teacher |
| GET | /api/students/{id} | - | 详情（StudentVO，**无密码**） | 登录 |
| PUT | /api/students/{id} | body: StudentUpdateDTO | 修改 | admin/teacher |
| DELETE | /api/students/{id} | - | 逻辑删除 | admin |
| GET | /api/clazzes / POST /api/clazzes / PUT /api/clazzes/{id} / DELETE /api/clazzes/{id} | 常规 | 班级 CRUD | 同上 |
| GET | /api/clazzes/{id}/students | - | 班级学生名单 | 登录 |
| GET | /api/courses / POST /api/courses / PUT /api/courses/{id} / DELETE /api/courses/{id} | 常规 | 课程 CRUD | 同上 |
| POST | /api/enrollments | body: studentId,courseId | 选课 | admin/teacher |
| DELETE | /api/enrollments/{id} | - | 退课（有成绩时拒绝，事务校验） | admin/teacher |
| POST | /api/scores | body: courseId,examType,items[{studentId,value}] | 按课程批量录成绩 | teacher(本课)/admin |
| GET | /api/scores/student/{studentId} | ?examType | 学生成绩单 | 登录(本人或教师) |
| GET | /api/scores/course/{courseId} | ?examType | 课程成绩表 | 登录 |
| GET | /api/admin/users | ?status | 待审核教师列表 | admin |
| PUT | /api/admin/users/{id}/status | body: status | 审核通过/禁用 | admin |

## 6. 认证、权限、校验、异常、密码安全方案

| 主题 | 方案 |
|---|---|
| 认证 | 登录成功签发 JWT（subject=userId，claim：name/role），有效期 2h（沿用现有配置）。前端存 localStorage，axios 请求头带 `Authorization: Bearer xxx`。**现有 JwtAuthenticationFilter 保留，升级点：从 JWT 里解析 role，构造带 authorities 的 Authentication** |
| 授权 | Spring Security 方法级注解：Controller/Service 上 `@PreAuthorize("hasRole('ADMIN')")` 等。角色：ADMIN、TEACHER（学生二期加 STUDENT）。配置沿用 STATELESS + csrf disable + login/register 放行 |
| 参数校验 | 沿用 @Valid + jakarta 注解；**补充**：DTO 与实体彻底分离（学生 DTO 去掉现有混入的 id 字段）；分组校验（新增/更新不同规则） |
| 异常处理 | 新建 `BusinessException(code,msg)` 业务异常基类；GlobalExceptionHandler 统一处理：BusinessException→对应 code、MethodArgumentNotValid→400+字段错误、DuplicateKeyException→409"重复提交"（解决现状 P3）、AccessDenied→403、兜底 Exception→500（日志记录，不泄露堆栈）。**修复 NameOrPasswordError 的 400/401 不一致：未认证统一 401** |
| 密码安全 | BCrypt（沿用）；登录错误信息统一"用户名或密码错误"（不暴露哪个错）；**GET 接口一律返回 VO，不含 password 字段**；application.yaml 密码改 `${DB_PASSWORD:}` 环境变量注入，配 `.env.example`（不含真值）入 git |
| 其他安全 | JWT_SECRET 继续走环境变量；CORS 仅放行前端 dev 地址；逻辑删除防物理误删 |

## 7. 页面列表与操作流程

| 页面 | 路径 | 主要操作 |
|---|---|---|
| 登录页 | /login | 登录（无token访问任何页→跳这里） |
| 注册页 | /register | 教师注册→提示"等待审核" |
| 主布局 | / | 侧边菜单（按角色显示）+顶栏用户信息+退出 |
| 学生管理 | /students | 列表/分页/搜索 → 新增(弹窗表单) → 编辑 → 删除(确认框)；行点击进详情 |
| 班级管理 | /clazzes | CRUD + "查看学生"跳转学生列表（带 clazzId 过滤） |
| 课程管理 | /courses | CRUD + "选课管理"入口 |
| 选课管理 | /courses/:id/enrollments | 左侧未选学生列表、右侧已选列表，添加/移除 |
| 成绩录入 | /courses/:id/scores | 选考试类型→表格列出全班学生→逐个填分→整班提交 |
| 成绩查询 | /scores | 按学生查成绩单（表格） |
| 用户审核 | /admin/users | admin 专属：待审核列表→通过/禁用 |

核心流程（前后端交互）：登录→存 token→路由守卫校验→加载菜单→各页面 axios 请求 `/api/**`→axios 拦截器统一处理 401（踢回登录）和业务错误（ElMessage 弹错误消息）→ 分页列表用 Element Plus Table+Pagination。

## 8. 测试策略与验收标准

| 层 | 策略 | 工具 |
|---|---|---|
| 单元测试 | Service 层核心业务：注册查重、登录成败、录成绩校验（用 Mockito 隔离 Mapper） | JUnit5+Mockito |
| 接口测试 | 每个 Controller 的正常路径+异常路径（401/403/400/409），用测试库（profile=test，独立 schema） | MockMvc / @SpringBootTest |
| 手工验收 | 前端页面走查：登录→各页面操作闭环 | 浏览器 |

核心验收标准（示例，全部要可复现）：
1. 注册重名学号→返回 409，提示"学号已存在"，数据库中无重复行（**并发场景由唯一索引兜底**）。
2. 错误密码登录 3 次→均返回 401，响应体不含"密码错误/用户不存在"区分。
3. 带 token 访问 /api/students→200；不带→401；teacher 访问 /api/admin/users→403。
4. 录入成绩 89.5→成绩单显示 89.5；录入 150→400 参数校验拦截。
5. 退选已有成绩的课程→409 拒绝；退选无成绩课程→成功且成绩级联可查为空。
6. GET /api/students/{id} 响应 JSON 中**不存在 password 字段**。
7. `mvnw test` 全绿；前端 `npm run build` 无错误。

## 9. 本地开发、运行、验证与部署思路

| 环节 | 做法 |
|---|---|
| 日常开发 | 后端：IDEA 直接跑 DemoApplication（改代码自动重启可用 devtools）；前端：`npm run dev`（Vite 热更新），代理 /api 到 8080 |
| 环境变量 | `.env.example` 列出 JWT_SECRET、DB_PASSWORD，本地 `.env` 不入 git；命令行构建沿用已验证的 `mvnw -s D:\develop\...\settings.xml` 方式 |
| 数据库变更 | 每个阶段的建表/改表 SQL 存 `db/migration/V*.sql`（手写编号脚本，不引入 Flyway 以减负；脚本同时是文档） |
| 验证 | 每完成一个模块：跑测试→Swagger/Postman 过一遍接口→前端页面走查 |
| 部署（后期） | 最简：`mvnw package` 出 fat-jar，任意一台 Windows/Linux 服务器 `java -jar demo.jar`（配环境变量）；前端 `npm run build` 产物由 Nginx 托管并反代 /api。课程演示可只跑本机 |
