# 开发路线图

> 对应推荐方向 B（一体化平台，二期接方向 C 数据分析），拆解依据：《项目现状分析》的问题清单 + 《技术方案与数据库设计》的 MVP。
> 里程碑：**M1 修好现有项目 → M2 完整后端（多表+权限）→ M3 前端联调演示 → M4（二期）数据分析**。

---

## 阶段 0：环境与地基修复（现状问题清零）

**目标**：现有项目从"能跑"变成"干净可维护"，并建立工程化习惯。
**前置依赖**：无（现在就能做）。

| # | 任务 | 涉及文件 |
|---|---|---|
| 0.1 | `git init` + 首次提交 + `.gitignore`（target/、.idea/、*.iml、.env） | .gitignore（新建） |
| 0.2 | 密码出代码：yaml 中 DB 密码/JWT_SECRET 改 `${DB_PASSWORD:}`/`${JWT_SECRET:}` 环境变量，新建 `.env.example`（假值示例）与 IDEA 运行配置说明 | application.yaml、.env.example |
| 0.3 | 包重构（IDE 重命名，不改逻辑）：`Controller`→`controller`、`Service`→`service`、`Mapper`→`mapper`、`Entity`→`entity`、`DTO`→`dto`、`Utils`→`util`、`Config`→`config`、`Exception`→`exception`、`ExceptionHandler`→`exception`；`Day1/Result`→`common/Result`；`StudentHasExisit`→`StudentAlreadyExistsException`；同步改 @MapperScan | 全部源码（纯移动+重命名） |
| 0.4 | 统一 JAVA_HOME 到 jdk-26（PATH 的 17 仅是干扰源，构建实际用 26，写进 README 说明即可，不必卸载） | README.md（新建） |
| 0.5 | JDBC URL 补 `allowPublicKeyRetrieval=true`；记录可用的命令行构建命令 | application.yaml、README.md |

**学习资料**：《资料检索清单》§3 阶段1；Spring Boot 外置配置文档。
**验收标准**：重构后 `mvnw test` 依然 BUILD SUCCESS；`git log` 有首次提交；yaml 中无任何明文密码。
**可能的问题**：IDEA 重构遗漏 @MapperScan 字符串引用（编译不报错、启动才报）→ 重构后必跑一次 contextLoads。
**验证方式**：完整跑一遍 test；`grep` 全项目确认无明文数据库密码/旧包名残留。
**现在不做**：不改任何业务逻辑、不建新表——本阶段只动"壳"。

**目标**：修复 P1/P2/P3/P7/P9 等数据层问题，把学生模块补成完整 CRUD。
**前置依赖**：阶段 0 完成。

| # | 任务 | 涉及文件 |
|---|---|---|

| 1.2 | 实体对齐：LocalDate→LocalDateTime、gender 语义注释、新增 studentNo | entity/Student.java |
| 1.3 | MetaObjectHandler 实现 createTime/updateTime 自动填充 | config/MybatisPlusConfig.java（新建） |
| 1.4 | 学生 CRUD 完整化：列表分页（MP 分页插件+条件构造器按 name/studentNo/clazzId 筛选）、新增、修改、逻辑删除 | StudentController/Service/Mapper、common/PageResult |
| 1.5 | StudentVO（无密码）替代实体直接返回 | dto/StudentVO（新建） |

**学习资料**：MP 分页/自动填充/逻辑删除文档；MySQL CREATE TABLE。

**可能的问题**：改表时现有数据 gender 是 char('0'/'1') 需转换（`update ... set gender=gender-0` 或脚本迁移）；分页插件不配 Count 会全表查。
**验证方式**：测试全绿 + Postman 手工过一遍 + `SHOW INDEX FROM student` 核对索引。
**现在不做**：不做班级/课程表（下一阶段）；不引入 Flyway。

## 阶段 2：统一异常、参数校验、响应规范

**目标**：把"接口质量基建"一次做对（P4/P5/P8/P12 清零）。
**前置依赖**：阶段 1。

| # | 任务 | 涉及文件 |

| 2.2 | GlobalExceptionHandler 重写：业务异常→对应码、DuplicateKey→409、AccessDenied→403、兜底→500(记日志不泄堆栈)；**修复 NameOrPasswordError 的 HTTP 401 与 body code 不一致** | exception/GlobalExceptionHandler |
| 2.3 | Result 字段 `object`→`data`（保留旧字段一个版本兼容或一次性全改——推荐全改，项目还未有前端消费方） | common/Result |
| 2.4 | 校验增强：DTO 去掉混入的 id；新增/更新分组校验；错误消息中文友好 | dto/ |

**现在不做**：不做国际化、不做响应加密。

## 阶段 3：注册登录与角色权限（RBAC 落地）

**目标**：把现有"人人同权"升级为 admin/teacher 双角色。
**前置依赖**：阶段 2。

| # | 任务 | 涉及文件 |
|---|---|---|
| 3.1 | 建表 V3__create_user.sql（见技术方案 §4.6）+ User 实体/Mapper | db/migration/、entity/User |
| 3.2 | 登录改造：user 表登录，JWT claim 加 role；JwtAuthenticationFilter 解析 role→authorities；LoginUser 上下文工具（Controller 里取当前用户） | security/ |
| 3.3 | teacher 注册→status=0 待审核；admin 审核 API；status!=1 登录拒绝 | AuthController、AdminUserController（新建） |
| 3.4 | SecurityConfig 加 @EnableMethodSecurity；接口按方案 §5 标注 @PreAuthorize | config/SecurityConfig |
| 3.5 | 修改密码接口（校验旧密码） | AuthController |
| 3.6 | 权限测试：admin/teacher/未登录三种身份矩阵 | test/ |

**学习资料**：Spring Security Web 配置文档；jjwt 0.12 官方 README（注意 parser API 与旧教程完全不同）。
**验收标准**：① 无 token→401；② teacher 访问审核接口→403；③ 待审核账号登录→403+提示"等待管理员审核"；④ token 中 role 与实际权限一致。
**可能的问题**：现有 StudentController 的注册登录接口与 user 表并存造成两套账号——**决定：现有 student 表保留 password 但登录统一走 user 表，student.password 二期学生自助时启用**；JWT 密钥泄露风险→部署时换强密钥。
**验证方式**：权限矩阵测试全绿；手动伪造 token→401。
**现在不做**：不做刷新 token、不做记住我、不做验证码。

## 优先级总览：先做什么、不做什么

```
必须按序：0 → 1 → 2 → 3 → 4 → 5 → 6   （每阶段验收通过才进下一阶段）
可以并行：README 文档随时写；测试随模块同步写（不要最后补）
应该推迟：考勤、Excel、ECharts、学生自助端、springdoc（阶段6再验证）
永远不做（本项目范围内）：微服务、MQ、Redis、分布式、OAuth2、多租户
```

## 每阶段的通用完成定义（DoD）

1. 该阶段所有验收标准逐条通过；2. `mvnw test` 全绿；3. git 提交（信息写清做了什么）；4. 文档同步更新（README/接口清单）；5. 自测过一遍主流程再开始下一阶段。
