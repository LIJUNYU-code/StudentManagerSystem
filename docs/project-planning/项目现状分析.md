## 4. 已确认的问题（代码+数据库实测，按严重程度排序）

### 🔴 高优先级（影响正确性/安全）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| P1 | **gender 类型不匹配** | 实体 `Integer gender` vs 数据库 `gender char(1)` | 插入 `1` 到 char(1) 可运行但隐式转换脆弱；查询结果 `1`→`Integer` 靠驱动转换，随时可能因模式严格化而断 |
| P2 | **name 无唯一索引** | `SHOW INDEX FROM student` 只有 PRIMARY(id) 和 phone 唯一键 | 注册查重是"先查后插"，并发下两个请求可同时通过查重 → 出现重名数据；且 `selectByName` 返回单对象，一旦重名，登录接口直接抛 TooManyResultsException |
| P3 | **查重字段与唯一约束错位** | 业务按 name 查重，但唯一索引在 phone | 重复 phone 注册 → DuplicateKeyException 未捕获 → 500 错误；重名却拦不住（见 P2） |
| P4 | **接口返回密码哈希** | GET /student/{id} 直接返回 Student 实体 | password（BCrypt 哈希）、可能敏感字段全部泄露给前端 |
| P5 | **NameOrPasswordError 状态码不一致** | 处理器返回 `Result.error(401,...)` 但 HTTP 状态是 400 | 前端无法凭 HTTP 状态码判断"没登录"还是"参数错" |
| P6 | **数据库密码明文** | application.yaml 中 datasource.password 为明文 | 密码会随代码提交泄露；本地学习项目风险可控但属坏习惯 |

### 🟡 中优先级（影响质量/可维护性）

| # | 问题 | 说明 |
|---|---|---|
| P7 | 时间类型用 LocalDate | DB 是 datetime，LocalDate 丢时分秒，update_time 无法体现同日内多次修改 |
| P8 | `@Select("select * from student where name=#{name}")` 无 `LIMIT 1` | 与 P2 叠加：重名即异常；`select *` 也把 password 查出来 |
| P9 | 无 MetaObjectHandler | `@TableField(fill=...)` 形同虚设，时间靠 Service 手动 set，容易漏 |
| P10 | 包名大写（`Controller`/`Service`/`Mapper`...）+ 教学包 `Day1` 混在主代码里 + `StudentHasExisit` 拼写错误 | 不符合 Java 规范，IDE 提示拼写错误，影响可读性与专业度 |
| P11 | 字段注入 `@Autowired`（非构造器注入） | 不利于测试，官方推荐构造器注入 |
| P12 | 响应体字段名 `object` 语义不清；Result 放在 `Day1` 包 | 前端对接时困惑；教学痕迹应清理 |
| P13 | 无测试、无 SQL 脚本、无 README、无接口文档 | 重构和回归没有安全网 |

### 🟢 低优先级（环境/习惯）

| # | 问题 | 说明 |
|---|---|---|
| P14 | 未做版本控制（无 .git） | 任何改动不可回退，学习项目也应从第一天起 git init |
| P15 | JWT_SECRET 环境变量未设置 | 本地启动必须手动注入，否则启动失败；无 `.env` 或启动脚本约定 |
| P16 | 无连接池调优、JDBC URL 缺 `allowPublicKeyRetrieval`（caching_sha2_password 下首次连接可能报错） | 小问题，顺手修 |
